# Question-based Liu Yao: experimental scope

Status (2026-10-19): the question flow and production API are implemented with runtime/build-time feature gates and Turnstile requirements. Confirm the current deployed flag and hostname configuration before describing the feature as publicly open. This remains a separate question-based experiment, not part of the birth-chart report. It computes a core Ba Gong / Na Jia chart deterministically, but it is not a complete traditional Liu Yao judgement system.

## The narrow first version

Offer a separate “Ask a question” flow for reflective, non-emergency decisions. The user writes one specific question, selects a timeframe, and casts six lines with a transparent three-coin interaction. The first throw records the local cast time and IANA time zone. Display the original and changed hexagrams, plus an expandable Na Jia board with palace, sequence, Shi/Ying, stems/branches, five elements, six kin, six spirits and moving lines. Missing kin are labelled candidates, not automatically designated as the useful spirit. The API returns the six recorded 6/7/8/9 values and all deterministic facts so a result can be reproduced and audited. It must not silently re-roll until an answer feels favourable. The current UI keeps the question, cast, cast context, and answer in tab-scoped `sessionStorage`, discloses that temporary local storage, and offers a clear action. A portable user-controlled export is still desirable before wider beta.

The first answer should say: what the image suggests, one plausible opportunity, one risk/condition, what information is still missing, and one practical next step. Keep the traditional rationale expandable. This is a reflective interpretation, not a factual prediction or professional advice. Exclude emergency, medical, legal, investment, and safety-critical questions from personalised forecasts; give an honest limitation instead.

## Calculation and evidence gate

Implemented convention: each coin gives 3 for heads or 2 for tails. The three-coin sum is 6 (old yin, moving), 7 (young yang), 8 (young yin), or 9 (old yang, moving). The first throw is the bottom line. The browser uses `crypto.getRandomValues` for three independent coin outcomes; the server validates all six totals and derives the chart from them. The implementation includes common Ba Gong palace membership and sequence, Shi/Ying positions, trigram Na Jia, branch elements, six-kin generation/control relationships, pure-palace missing-kin candidates, and six spirits from the local cast day's stem. The AI receives these computed facts but may not calculate or alter them. The chosen mapping is explicit because schools and口诀 differ; the product does not claim it is the only valid convention. `tests/iching.test.mjs` covers all stable yin/yang, moving-line transformations, Tai/Fou and Gou/Xiao Chu orientation, all 64 palace/sequence assignments, representative Na Jia/six-kin assignments, a timezone-sensitive day-stem/six-spirit case, malformed casts, and a changed-hexagram regression.

Still out of scope: month branch and day branch interactions (月建、日辰), strength/旺衰, 空亡, 合冲刑害, 六神-specific judgement, automatic question-category/useful-spirit selection (用神), and school-specific line judgement. The model is not allowed to invent those layers. The cast date is used only for the declared day-stem six-spirit start rule; this is not a full date-based judgement.

Reference checks: [Chinese Text Project, Hexagram 11 Tai](https://ctext.org/book-of-changes/tai) and [Hexagram 12 Fou](https://ctext.org/book-of-changes/fou/ens) distinguish upper/lower trigram order; [Unicode's official 64-hexagram names](https://www.unicode.org/charts/PDF/U4DC0.pdf) checks the ordered names. An online 8×8 table was found with its axes apparently reversed, so do not copy a table without checking Tai=upper Kun/lower Qian and Fou=upper Qian/lower Kun.

Historical sources distinguish three-coin casting from yarrow-stalk methods; the product should identify which one it uses and avoid implying that every school interprets the resulting hexagram the same way. Na Jia, Shi/Ying, six kin and six spirits were cross-checked against [《卜筮正宗》以钱代蓍法](https://www.quanxue.cn/qt_mingxiang/boshi/boshi05.html), [纳甲与世应](https://www.quanxue.cn/qt_mingxiang/boshi/boshi07.html), and [六兽起例](https://www.quanxue.cn/qt_mingxiang/boshi/boshi08.html). These are tradition-specific references, not scientific validation. Background: [Chinese Text Project, historical note on coin casting](https://ctext.org/dictionary.pl?chapter=236181&if=en&sid=11470&trid=124789) and [Book of Changes, Shuo Gua](https://ctext.org/book-of-changes/shuo-gua/zh).

## Release gate

Keep public access gated until the deterministic chart tests, bilingual explanation, privacy review, and a small novice usability check pass. The first three have local evidence; the novice check is still outstanding. Both `NEXT_PUBLIC_QUESTION_BETA_ENABLED=true` (build-time public link/page) and `QUESTION_BETA_ENABLED=true` (server API) are required to open the production experiment; the API also requires a configured Turnstile site key, secret, and `TURNSTILE_HOSTNAMES` with only approved production domains. It checks action `iching` and the siteverify hostname. Confirm the current deployed values rather than assuming the feature is open or closed. A real-token success/replay check is still needed before activation. The current in-memory per-isolate rate limit is not a global anti-abuse control. Do not claim greater predictive accuracy than BaZi without real consented evaluation.

For the novice check, observe at least three first-time users (one on a phone) trying to phrase a question, select a timeframe, cast six lines, find the answer, and explain in their own words what the tool did and did not calculate. Ask whether the moving lines and the “why” section were comprehensible and whether the answer affected a real decision more strongly than intended. Record confusions and time to answer, not “accuracy.” Fix any misunderstanding that this is a complete Na Jia reading before enabling the flags.
